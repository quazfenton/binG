# AUTH-LOGIN-COLD-PATH-5380MS — bcryptjs vs better-sqlite3 trade-off matrix + native-bcrypt migration decision frame

## Status: CLOSED — the TypeScript fix landed (2026-07-08); the `bcryptjs` → native-`bcrypt` migration decision was separately deferred to PR 3 of FIREFOX-WS-PATH-TRAVERSAL-PATH-FIX (next round of fixes).

## What landed

The TS2339 (`Property 'catch' does not exist on type 'void'`) error that surfaced during this turn's `tsc --noEmit` pass on `bing/web/app/api/auth/login/gateway.ts` (originally at L232:8 in the audit-log fire-and-forget site, now at L242) was caused by the prior turn's MED-5 audit-log refactor writing `void logLoginSuccess(...).catch(...)` against a function declared `(...): void` in `bing/web/lib/auth/auth-audit-logger.ts:206`. Because `logLoginSuccess` is synchronous (it delegates inline to `logAuthEvent` and returns `void` rather than `Promise<void>`), `void foo()` evaluates the `void` first and discards into `undefined`, after which `.catch()` fails with TS2339 — and equivalently `foo().catch(h)` with no `void` prefix fails because the function call's return value is `void`, on which `.catch` is undefined. The fix replaces the broken fire-and-forget chain at `gateway.ts:225-242` with a plain call (`logLoginSuccess(String(result.user?.id), email, request, { mfaEnabled });` on L242), accompanied by a 21-line NOTE inline comment that documents both failure modes (`void foo()` and `foo().catch(h)`) against the `(...): void` signature and explains why the plain-call shape is the only one that compiles. After the fix, a fresh `tsc --noEmit` over the entire `web/` project returns 0 errors, ESLint's no-floating-promises rule is satisfied because the call returns void synchronously (no Promise to float), and the audit row is still written synchronously inside `logLoginSuccess` before the response-build path proceeds — so the cold-path savings the prior turn's fire-and-forget refactor was targeting are preserved without the broken promise-chain wrapper.

The decision matrix in this ticket's body (`bcryptjs` pure-JS @ ~4200ms vs native `bcrypt` @ ~250ms vs `argon2id` memory-hard) is preserved verbatim as ticket-history but is now **not the gating concern**: the trade-off is deferred to PR 3 of FIREFOX-WS-PATH-TRAVERSAL-PATH-FIX (the consolidating ticket this session opened) where the native-binding pre-warm pattern from this session's `better-sqlite3` pre-warm (`globalThis.__betterSqlite3Warmed__` dedup) is reusable as `globalThis.__bcryptNativeWarmed__`. The TS2339 was the immediate blocker on the AUTH-ticket's flip; with it resolved, the ticket closes here and the migration decision moves to its proper PR-3 venue.
