# Oracle Cloud Always-Free deploy

Single ARM A1 VM (4 OCPU / 24 GB free forever) hosts:

| Container   | Public hostname        | Purpose                                |
|-------------|------------------------|----------------------------------------|
| `caddy`     | —                      | TLS termination + reverse proxy        |
| `backend`   | `api.${DOMAIN}`        | Hono orchestrator (chat, SSE, agents)  |
| `ninerouter`| `router.${DOMAIN}`     | 9Router BYOK / OAuth LLM gateway       |
| `worker`    | (internal only)        | BullMQ workers (optional, off by default) |

The Vercel frontend stays where it is and only needs two env vars added.

---

## 1. Provision the VM (one-time)

In the OCI Console → **Compute → Instances → Create Instance**:

- Image: **Canonical Ubuntu 22.04** (or Oracle Linux 8)
- Shape: **VM.Standard.A1.Flex** — 4 OCPU, 24 GB RAM (Always Free)
- Networking: Assign public IPv4
- SSH: paste your public key
- **Advanced → Cloud-init**: paste the contents of [`cloud-init.yaml`](./cloud-init.yaml)

Or via CLI (when `oci` is on PATH):

```bash
oci compute instance launch \
  --availability-domain "<AD>" \
  --compartment-id "<OCID>" \
  --shape VM.Standard.A1.Flex \
  --shape-config '{"ocpus":4,"memoryInGBs":24}' \
  --image-id "<UBUNTU_ARM_IMAGE_OCID>" \
  --subnet-id "<SUBNET_OCID>" \
  --assign-public-ip true \
  --ssh-authorized-keys-file ~/.ssh/id_ed25519.pub \
  --user-data-file infra/oracle/cloud-init.yaml \
  --display-name bing-prod
```

After ~3 min the VM has Docker, Compose, UFW, fail2ban, and the firewall opened on 80/443.

> Oracle's default Security List also blocks 80/443 — open them under **Networking → VCN → Security Lists**.

---

## 2. DNS

Point two `A` records at the VM's public IP:

```
api.example.com      A   <PUBLIC_IP>
router.example.com   A   <PUBLIC_IP>
```

---

## 3. Deploy

```bash
ssh ubuntu@<PUBLIC_IP>
sudo -i
cd /opt/bing
git clone https://github.com/quazfenton/binG .
cp infra/oracle/.env.example .env       # generated by cloud-init
nano .env                                # fill DOMAIN, ACME_EMAIL, secrets
docker compose -f infra/oracle/docker-compose.yml --env-file .env up -d --build
docker compose -f infra/oracle/docker-compose.yml logs -f
```

Caddy will auto-issue Let's Encrypt certs on first hit. Verify:

```
curl https://api.${DOMAIN}/health
curl https://router.${DOMAIN}/health
```

---

## 4. Wire Vercel

In **Vercel → Project → Settings → Environment Variables** add:

| Key                        | Value                              |
|----------------------------|------------------------------------|
| `BACKEND_URL`              | `https://api.example.com`          |
| `NEXT_PUBLIC_BACKEND_URL`  | `https://api.example.com`          |
| `NINEROUTER_BASE_URL`      | `https://router.example.com`       |
| `NINEROUTER_ADMIN_KEY`     | (same as on the VM)                |

Then redeploy. `web/proxy.ts` already rewrites `/api/chat` to `BACKEND_URL`.

> Tip: for SSE/streaming, switch the chat client to `fetch(NEXT_PUBLIC_BACKEND_URL + '/api/chat', …)` so traffic skips Vercel's edge timeout entirely.

---

## 5. Updates

```bash
ssh ubuntu@<PUBLIC_IP>
cd /opt/bing && git pull
docker compose -f infra/oracle/docker-compose.yml up -d --build
```

---

## 6. Where Netlify fits

Netlify is **not** suitable for `/api/chat` (SSE timeouts). It is useful for:

- thin edge wrappers (geo-routing, abuse blocking) in front of `api.example.com`
- short-lived webhook receivers (Stripe, GitHub, etc.)

A starter [`netlify.toml`](../../netlify.toml) is included for that purpose; deploy with `netlify deploy --prod` from the repo root once the CLI is on your PATH.
